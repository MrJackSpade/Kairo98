# Artwork intake

The 360-pixel catalog images were approved for inclusion in Git and the development APK on 24 September 2026. `tools/build_review_catalog.py` imports 6,123 images from the local gallery into the `withImages` flavor and records each source URL and packaged SHA-256 in `app/src/withImages/assets/art/catalog-provenance-v1.json`. The tagged workflow now attaches a `withImages` APK to GitHub Releases, but the separate artwork rights audit remains incomplete. That audit must establish the creator and applicable redistribution and derivative rights for both the free GitHub and paid Play builds before the artwork APK can be described as release-ready.

`tools/import_art.py` remains the strict importer for individually documented assets. It requires a source file, SHA-256, creator, source, license or permission basis, and affirmative rights for both distribution channels and resizing. Its generated `art/provenance-v1.json` was used for the earlier synthetic fixture, not the current bulk catalog.

The two PNGs in `docs/fixtures/art-source/` are original synthetic test fixtures created for this project. They contain no game screenshot or publisher box art. The project can bundle and resize these fixtures in both distribution channels. Their source hashes and this permission basis are recorded in the fixture manifest. They test the import path for one synthetic content ID; they do not imply permission for any real game media.

LaunchBox's [Games Database media guide](https://feedback.launchbox-app.com/en/help/articles/7997304-using-games-database-media-in-launchbox) describes downloading images into a local LaunchBox library, and its [database introduction](https://feedback.launchbox-app.com/en/help/articles/8890692-getting-started-with-the-launchbox-games-database) describes a community-maintained collection. Those pages do not establish redistribution rights for each image in another app. The packaged provenance keeps source references available for the release audit; screenshot, box scan, and fan art rights may differ.

The first [candidate inventory](art-candidates.md) recorded a box front and screenshot for the known test title. The new bulk catalog includes reviewed downscaled images, but creator and redistribution rights remain to be audited.

Run `python tools/build_review_catalog.py` from the repository root to rebuild the bundled catalog from the ignored local 360-pixel gallery. The script emits 134 games with 213 content IDs, a 3,342-game name index, and 6,123 WebP images. The art uses 114,812,216 bytes. Library rows decode box art on a worker thread and game pages decode screenshots. Missing art falls back to the resolved title, then the filename.

The importer stages conversions before modifying packaged files. A rejected record leaves existing catalog and art files intact. On a later approved-manifest update, it removes references and generated WebP files for assets no longer present; the catalog generator also removes obsolete generated shards. The importer requires provenance when an art directory already contains WebP files so unknown files are not silently adopted.

At source revision `40d2fd9`, `:app:assembleDebug` and `:app:bundleRelease` succeeded. The resulting debug APK and release AAB each contained the same six `art/` and `catalog/` files, including both WebP images and the provenance manifest; per-file SHA-256 comparisons found zero differences. This verifies asset parity in the two build formats, before signing, Play delivery, or installation of a release variant.

The prior synthetic fixture check at core revision `50d406d` is historical. The Retroid debug build displayed canonical titles and bundled box images in the library and a screenshot and authored description on the Black Onyx game page. The `withImages` and `withoutImages` debug APKs contained 147 identical shared assets; the former added 6,124 `art/` assets, including the provenance JSON. `tools/audit_play_release.py` checks the release APK split, provenance manifest, required notices, and shared assets after each tagged build.
