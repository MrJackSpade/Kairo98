## Writing release notes

Create `vX.Y.Z.md` before pushing each version tag, and add it to the table above. The tag workflow requires the file and publishes its contents verbatim. Describe only changes in that release and any install impact, checked against the previous tag. Keep audit status, device test status, roadmaps, and generic build commentary out of the notes.
